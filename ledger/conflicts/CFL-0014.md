## State: `resolved` (`scoped`)

## Classification

**Type C1 — scopable.** Both claims come from one source, SRC-00025 (*Hot-Cold Tiering of HBM and
High Bandwidth Flash for Agentic LLM Serving*), and report two different metrics from the same
simulation run at the same concurrency level:

> "At Na = 48, HBF adds 0.084 ms of overhead while NVLink-C2C adds 1.0 ms and PCIe adds 7 ms."
> "In contrast, our design with tiering reports 14 ms per token at Na = 48 (72 tok/s) and 27 ms
> at Na = 128 (37 tok/s) per agent, both safely within the 50 ms SLO."

`CLM-ARCH-0019` is the latency overhead contributed by the HBF memory tier; `CLM-ARCH-0020` is the
end-to-end time-between-tokens (TBT) of the whole serving system, of which the tiering overhead is
only one component. These were never the same measurement — a component's overhead is not in
tension with the system total it contributes to. The pair looked comparable only because neither
claim's `conditions` recorded *what quantity* the time value belongs to; both shared
`concurrency_n_a: 48`, which is a workload operating point (like frequency or voltage), not a
subject-identifying condition, but it was the only condition either claim carried that the other
also named, so the detector matched on it by default.

## Resolution

Added a `component` condition to both claims (`HBF tiering resume/access latency overhead` on
`CLM-ARCH-0019`, `end-to-end time-between-tokens (TBT)` on `CLM-ARCH-0020`), in `conditions` and
`quantity.conditions`, matching the `component` convention already used elsewhere in this ledger
(e.g. `CLM-ARCH-0002`). The two claims now state different values for a shared condition
(`component`), so `conditions_conflict` excludes the pair from future comparison. `concurrency_n_a`
was left as-is rather than added to `reference/comparability.yaml`'s `operating_keys`: it is
plausibly an operating point in general, but generalizing from one paper risks silently loosening
comparability for other ARCH claims that legitimately share it as a subject-identifying condition;
that question is deferred until more concurrency-keyed claims exist to judge it against. Recorded
as a non-public correction on both claims: the digest that cited the unscoped conditions
(2026-09-23) was blocked from deploy by this same conflict and never reached readers.
